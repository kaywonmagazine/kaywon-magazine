# EX MAGAZINE

기존 EXD MAGAZINE 백엔드의 공개 콘텐츠 API를 사용하는 웹 프런트엔드입니다. CSS와 JavaScript는 별도 파일로 유지합니다.

## 페이지 구성

- `index.html`: 메인
- `work.html`, `people.html`, `life.html`, `view.html`: 카테고리
- `article.html?id=기사ID`: 공통 기사 상세
- `work.html?subcategory=졸업전시`: 세부 분류 예시
- `work.html?view=articles`: 소개 영역 없는 전체 기사 목록 예시
- `404.html`: 이전 개별 HTML 주소를 새 공통 주소로 안내하는 GitHub Pages 호환 페이지

112개 화면별 HTML을 6개 공통 페이지와 이전 주소 안내 페이지 1개로 통합했습니다. 세부 분류·목록·기사마다 HTML을 추가할 필요가 없습니다.

## 저장과 공개

편집실: https://ex-magazine-editorial-recovery.rhddyd0831.chatgpt.site/admin

GitHub Pages는 js/content.js의 공개 기사 복구본을 표시합니다. 편집실에서 업로드한 기사는 현재 GitHub Pages에 자동 반영되지 않습니다. 공개 읽기 API를 별도로 연결하는 경우 각 페이지의 body에 data-public-api를 설정할 수 있습니다.

## 미리보기와 게시

공개 사이트에 HTML과 css, js, assets, media, licenses 폴더를 함께 게시합니다. 편집실 소스와 복구 산출물은 .artifacts에 별도로 보관합니다.

- `css/styles.css`: 공통 스타일

## 기사 상태와 추가 사진

기사 관리 목록의 옵션에서 메인 관리자는 공개·비공개를 선택하거나 기사를 삭제할 수 있습니다. 현재 공개 여부에 따라 한쪽에만 체크가 표시됩니다. 공개 선택은 최신 저장 원고를 게시하며, 삭제는 확인 후 원고와 공개본을 제거합니다.

표지는 별도로 1장을 선택하고, 추가 사진은 최대 10장까지 선택할 수 있습니다. 기존 본문에 삽입한 사진도 추가 사진 수에 포함합니다. 추가 사진은 편집 화면에서 순서를 바꾸거나 제거할 수 있고, 공개 기사 본문 아래의 슬라이더에 표시됩니다. 사진을 클릭하면 확대 창이 열리며 좌우 버튼·키보드 방향키로 넘기고 Esc로 닫을 수 있습니다.

GitHub Pages의 추가 사진 기능에는 각 HTML 파일과 `js/app.js`, `js/gallery.js`, `css/gallery.css` 변경을 함께 반영해야 합니다. 기존 관리자와 운영 사이트는 Sites 배포로 갱신합니다.

기사 옵션·추가 사진 갤러리 운영 배포: 버전 29, 소스 `4f5c24f4a9eaa4cf5b6017acfc5b4ab5d3189d88`.

## PDF 출력과 기사 일괄 관리

기사 상세 화면과 원고 편집 화면의 `PDF 출력` 버튼을 누르면 글꼴·사진을 불러온 후 브라우저 인쇄 창을 엽니다. 인쇄 대상에서 `PDF로 저장`을 선택하세요. 표지·본문·추가 사진을 모두 출력하고 메뉴·슬라이더 화살표·출력 버튼은 PDF에서 숨깁니다.

기사 관리 목록 왼쪽에서 기사를 개별 선택하거나 표 머리글의 체크박스로 현재 필터에 보이는 기사를 전체 선택할 수 있습니다. 우측 상단에서 선택 기사를 한 번에 공개·비공개·삭제하거나 PDF로 출력합니다. 필터를 바꾸면 선택을 초기화합니다. 여러 기사 PDF는 목록 순서대로 하나의 문서에 출력하며 기사마다 새 페이지에서 시작합니다. 관리 화면 PDF는 최신 서버 저장 원고, 공개 기사 화면 PDF는 현재 공개본을 사용합니다.

일괄 공개·비공개·삭제는 메인 관리자만 실행할 수 있습니다. 서버가 선택 기사 전체의 권한·수정 버전·입력 내용을 검사하며, 충돌이 있으면 일부만 적용하지 않고 변경을 중단합니다. 일괄 작업과 PDF는 한 번에 최대 200개를 지원합니다. 비공개 원고 PDF도 기존 작성 권한 검사를 거칩니다.

GitHub Pages 반영 시 HTML 파일, `js/app.js`, 새 파일 `js/article-print.js`, `css/article-print.css`를 함께 업로드하세요.

PDF 출력·기사 일괄 관리 운영 배포: 버전 30, 소스 `6761f8be3acde613ea30656bd742390dd640917b`.


## 업로드와 분류 반영

작성 화면의 업로드 버튼은 최신 원고를 서버에 저장한 뒤 선택한 주 분류·세부 분류로 공개하고 상태를 게시됨으로 변경합니다. 작성자는 본인 기사만 업로드할 수 있습니다. 메인 관리자는 모든 기사를 업로드할 수 있습니다. 저장 확인은 원고 저장만 수행하므로 기존 공개본을 갱신하려면 업로드를 눌러야 합니다. 이미 공개된 기사의 분류를 변경한 경우에도 업로드로 최신 분류를 반영합니다.

편집 화면은 초기 동기화가 끝난 후 입력할 수 있으며, 주 분류 변경 시 해당 분류의 세부 분류만 선택할 수 있습니다. 주 분류와 맞지 않는 세부 분류는 서버에서도 저장을 거절합니다.

분류 저장 안정화·명시적 업로드/게시됨 운영 배포: 버전 31, 소스 `2471e353854a1a7222f42719a12cc9ca9262d668`.
